# 과제 15: 퀵 정렬과 AVL 트리 정렬의 성능 비교

## 실행 방법
```
gcc -O2 -fno-optimize-sibling-calls -o quick_vs_avl quick_vs_avl.c
./quick_vs_avl
```

## 구현 및 측정 기준
- **데이터**: n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000개의 무작위 정수(중복 허용). 삭제 대상이 실제로 존재하는 경우가 생기도록 값의 범위를 `0 ~ 2n−1`로 했습니다. (범위가 너무 넓으면 삭제할 값이 거의 없어 삭제 연산이 의미가 없어집니다.)
- **퀵 정렬**: 피벗은 **세 원소의 중앙값(Median-of-Three)**을 사용했습니다(과제 12~14에서 비교 횟수가 가장 적었던 방법). 정렬 후 정렬된 배열에서 삽입·삭제를 합니다.
  - 삽입: 앞에서부터 선형 탐색하여 위치를 찾고(마지막으로 같거나 작은 값 뒤), 뒤의 원소를 한 칸씩 뒤로 이동
  - 삭제: 선형 탐색으로 값을 찾고(정렬되어 있으므로 더 큰 값을 만나면 중단), 있으면 뒤의 원소를 한 칸씩 앞으로 이동. 없으면 삭제하지 않음
- **AVL 트리**: 원본 데이터를 하나씩 삽입하여 정렬 상태를 유지하고, 이후 삽입·삭제도 트리에서 직접 수행합니다. 중복 값은 노드의 `count`에 저장하고, 삭제 시 `count`가 2 이상이면 1만 줄입니다. 자식이 둘인 노드를 삭제할 때는 오른쪽 서브트리의 최솟값 노드로 대체하며, 필요하면 회전으로 균형을 복구합니다.
- **삽입·삭제**: n의 20%(200 ~ 4,000회). 난수를 생성해 짝수이면 삽입, 홀수이면 삭제를 선택하고, 삽입·삭제할 값은 별도의 난수로 정합니다. 삭제할 값이 없으면 그 연산은 건너뛰며(탐색 비교는 셈) 연산 횟수에는 포함됩니다. 두 방법에 동일한 연산 순서와 값을 적용했고, 정렬 직후와 모든 연산 후 두 자료구조의 내용이 같은지 검증했습니다(최종 개수 일치).
- **총 수행시간**: 정렬(AVL은 전체 삽입) 시작부터 모든 삽입·삭제가 끝날 때까지. 난수 생성, 배열 복사, 검증(중위 순회), 출력은 제외합니다. 시간이 짧아서 같은 조건으로 30번 반복한 평균(ms)입니다.
- **비교 횟수**: 데이터 값 사이의 비교만 셉니다. 퀵 정렬은 분할 중 값 비교와 피벗 결정 비교, 삽입·삭제의 탐색에서 `a[pos]`와 값의 비교를 세고, AVL은 키 비교 한 번(작다/같다/크다 3분기)을 1회로 셉니다. 선형 탐색에서도 같은 방식(원소 하나당 1회)으로 셉니다. 균형 인수나 높이 비교는 제외합니다.
- **데이터 이동 횟수**: 데이터 값의 복사·대입 횟수입니다. 교환(swap)은 대입 3회, 배열의 한 칸 이동은 1회, 삽입 값 저장은 1회입니다. AVL은 새 노드에 키를 저장하는 것과 삭제 시 후계자 키를 복사하는 것을 1회로 세고, 포인터 연결 변경, `count`와 높이 갱신은 제외합니다.
- **메모리 사용량(최대)**
  - 퀵 정렬: (연산 중 최대 원소 수) × 4 Byte + 퀵 정렬 재귀 스택 최대 사용량
  - AVL: (최대 노드 수) × `sizeof(Node)`(32 Byte: 정수 3개 + 포인터 2개, 정렬 패딩 포함) + 삽입·삭제 재귀 스택 최대 사용량
  - 재귀 스택은 재귀 호출마다 지역 변수의 주소를 읽어 가장 깊을 때의 주소와 시작 주소의 차이로 측정했습니다. `malloc`이 붙이는 관리용 헤더는 포함하지 않아 실제 사용량은 AVL이 조금 더 큽니다.

## 분석

### 1. 총 수행시간과 비교 횟수
n=20,000에서 AVL 트리의 총 수행시간은 4.24 ms로 퀵 정렬 방식(31.33 ms)의 약 1/7이었고, 비교 횟수는 309,081회로 약 1/130이었습니다. 정렬 자체는 두 방법 모두 O(n log n) 수준의 일이지만, 정렬 이후 삽입·삭제 단계에서 큰 차이가 납니다.

- 배열은 위치를 찾으려고 앞에서부터 선형 탐색을 하므로 연산 하나에 평균 n/2번 정도의 비교가 필요합니다(n=20,000에서 연산 하나당 약 10,000회). 연산이 n의 20%이므로 전체 비교는 O(n²)입니다.
- AVL 트리는 트리 높이(약 log₂n)만큼만 키를 비교하므로 연산 하나가 O(log n)이며, 전체 비교 횟수(약 30만 회)는 처음에 n개를 삽입하는 비용이 대부분입니다. 정렬 단계만 놓고 보면 배열 기반 퀵 정렬이 더 빠를 수 있으나 이번 실험에서는 따로 측정하지 않았고, 전체 과정에서는 삽입·삭제 단계의 차이가 훨씬 컸습니다.

### 2. 데이터 이동 횟수
퀵 정렬 방식의 이동은 29,844,626회, AVL은 17,197회로 약 1,700배 차이였습니다. 정렬된 배열은 삽입·삭제 때마다 그 뒤의 원소를 모두 한 칸씩 밀거나 당겨야 해서 연산 하나에 평균 n/2개 정도의 대입이 발생합니다. AVL은 원소를 옮기지 않고 포인터만 바꾸므로 값 이동은 새 노드를 만들 때 키를 저장하는 경우와, 자식이 둘인 노드를 삭제할 때 후계자 키를 복사하는 경우에만 생겼습니다. (이 수치에는 포인터 변경이 포함되지 않으므로 회전 비용은 반영되지 않지만, 회전은 상수 개의 포인터 수정이라 영향이 작습니다.)

### 3. 메모리 사용량
메모리는 AVL이 훨씬 많았습니다(n=20,000에서 523,471 Byte로 퀵 정렬 방식의 86,528 Byte의 약 6배). 배열은 원소 하나당 4 Byte(정수)만 쓰지만, AVL 노드는 키 외에 `count`, 높이, 왼쪽·오른쪽 포인터까지 노드당 32 Byte를 사용하기 때문입니다. 중복 값은 한 노드에 모아 저장하므로 노드 수는 원소 수보다 적었지만(범위 2n에서 서로 다른 값은 약 80%), 노드당 크기가 8배라 이를 상쇄하지 못했습니다. 재귀 스택은 퀵 정렬과 AVL 모두 수 KB 이내로 전체에서 차지하는 비중이 작았습니다. 반대로 배열은 크기가 커지면 연속된 공간이 필요하다는 점이 있습니다.

### 4. 데이터 크기 증가에 따른 변화
n이 2배가 되면 연산 수도 2배가 되어, 배열 방식은 연산당 비용(n에 비례)과 연산 수(n에 비례)가 곱해져 비교 횟수와 이동 횟수가 약 4배씩 늘었습니다(예: 8,000 → 16,000에서 비교 6,659,297 → 26,984,634, 약 4.05배). 시간도 1.4 ms(4,000) → 5.3 ms(8,000) → 20.2 ms(16,000)로 약 3.7~3.8배씩 늘었습니다. AVL은 비교 횟수가 약 2.1~2.3배씩, 시간은 약 2.3~2.5배씩 늘어 n log n에 가까운 증가를 보였습니다. 그래서 n이 커질수록 두 방법의 격차가 벌어졌습니다(시간 비율: n=1,000에서 약 1.2배 → n=20,000에서 약 7.4배).

### 5. 삽입·삭제가 반복되는 환경에서 유리한 자료구조
삽입·삭제가 반복되는 환경에서는 AVL 트리가 유리합니다. 배열은 정렬 상태를 유지하려면 위치 탐색(O(n))과 원소 이동(O(n))이 모두 필요하지만, AVL은 탐색·삽입·삭제가 모두 O(log n)이고 회전만으로 균형을 유지하기 때문입니다. 반면 AVL은 메모리를 약 6배 더 쓰고 구현이 복잡하므로, 데이터를 한 번 정렬한 뒤 조회만 하거나 삽입·삭제가 거의 없는 경우에는 배열과 퀵 정렬이 메모리와 단순성 면에서 낫습니다. (정렬된 배열은 이진 탐색으로 위치를 찾으면 비교는 줄일 수 있지만, 원소 이동 O(n)은 그대로 남습니다.)삽입·삭제가 모두 O(log n)이고 회전만으로 균형을 유지하기 때문입니다. 반면 AVL은 메모리를 약 6배 더 쓰고 구현이 복잡하므로, 데이터를 한 번 정렬한 뒤 조회만 하거나 삽입·삭제가 거의 없는 경우에는 배열과 퀵 정렬이 메모리와 단순성 면에서 낫습니다. (정렬된 배열은 이진 탐색으로 위치를 찾으면 비교는 줄일 수 있지만, 원소 이동 O(n)은 그대로 남습니다.)
